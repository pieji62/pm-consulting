# Workshop glossary

| Term | Meaning here |
| --- | --- |
| Agent | Assistant that can act on files and run tools |
| Astro | Tool that turns a project into static pages |
| Static site | Public files prepared in advance, not private customer accounts |
| Backend | Server-side processing program, outside workshop scope |
| Git | Local file version history |
| GitHub | Service for storing projects and running checks |
| Repository | Project files, history and configuration |
| Commit | Explained save point with a SHA identifier |
| SHA | Exact revision identifier, not a password |
| Branch | Line of work for proposing changes |
| Pull request | Proposed change reviewed before integration |
| Merge | Integrating a proposal; not the same as publication here |
| Terminal | Window for running commands the agent can explain |
| Dependency | Another organization's tool used by the project |
| Lockfile | Exact resolved versions for repeatable installation |
| Build | Preparing files suitable for publication |
| CI | Automated checks after a change |
| Deployment | Sending a verified version to public hosting |
| Token | Action credential stored as a secret, never in chat |
| MFA | Additional account-access verification |
| Accessibility | Enabling people with different needs, including assistive technologies |
| Domain / DNS | Site name and records locating its services |
| Evidence | Result of an actually executed check |
