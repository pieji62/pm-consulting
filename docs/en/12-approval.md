# 12. Approve without surprises

Two approvals are required before creation: what you need and the proposed solution.
Neither authorizes publication or spending.

1. Read the name, content, pages, functionality, appearance and pending information.
2. Review exclusions, external services and possible costs.
3. Request corrections before approval; the revision number changes.
4. When satisfied, the agent will indicate a command such as:

       npm.cmd start -- approve projects/my-site requirements

5. The terminal displays the document. Personally type APPROVE 1, replacing 1 with
   the displayed revision. For the proposal, use proposal instead of requirements.
6. Do not ask the agent to type your approval. The local receipt identifies the
   revision; it is not a digital signature or legal proof of identity.

If approval does not match the current step, ask the agent to inspect state.
Never edit progress files to force advancement. Historical approval receipts retain
their original wording; translating the interface does not create new approvals.
