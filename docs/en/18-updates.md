# 18. Change your site

1. Open the site folder and say: "Use workshop-maintenance. I want to change..."
2. Explain with examples; the agent classifies it and records a new revision.
3. Review and approve new requirements and proposal. Earlier approvals remain in
   history but no longer authorize the new version.
4. Preview and request all checks again.
5. Review the change summary. A proposal in GitHub is a Pull request.
6. Authorize integration and publication as separate decisions. Merging into main
   runs tests and never automatically publishes this workshop's sites.

If a dependency update fails, leave the published site intact and seek help.
Do not click Merge to dismiss an alert. An instructor or professional handles
conflicts; you do not need to understand Git to ask for help.

To recover a version, request a new revision based on known-good work, then
verify and authorize again. Avoid deletion and force push.
